MODULAR DESIGN

=========================================================



Face Recognition must be implemented as a completely independent module.



The module must return



Person Name



Confidence Score



Examples



Name : Dad

Confidence : 98.4%



Name : Mom

Confidence : 97.1%



Name : Priya

Confidence : 96.8%



Name : Unknown

Confidence : 41.2%



The router must use the returned person name and confidence score to decide the next pipeline.



Routing Rules



If the recognized person name is "Unknown"



↓



Continue through the existing OpenAI Vision pipeline.



↓



Generate Professional Summary



↓



Generate Rich Structured Data



↓



Store everything in SQLite.



---------------------------------------------------------



If the recognized person name is any registered person



Examples



Dad



Mom



Me



Priya



Shalini



Grandmother



Sister



etc.



↓



Skip OpenAI Vision completely.



↓



Use the existing Qwen pipeline.



↓



Store the actual recognized person's name in SQLite.



↓



Continue with the existing Telegram + Groq pipeline.



The actual recognized person's name must always be stored in SQLite.



Never replace the person's identity with generic values such as



Known Person



Known



Recognized Person



or similar placeholders.



Telegram and Groq should always answer using the real person's name.



Example



Dad entered the house at 8:42 AM.



Mom left the house at 5:18 PM.



Priya arrived carrying a parcel.



Unknown person entered at 2:31 PM carrying a cardboard box.



The Face Recognition module must only determine



Person Name



Confidence Score



The router is responsible for deciding whether to use OpenAI Vision or Qwen based on the recognition result.



This separation of responsibilities must always be maintained.
